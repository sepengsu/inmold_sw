### Cam_test — 실시간 카메라·RS232 테스트

`Cam_test.py`는 모델을 불러오지 않고 카메라 영상을 계속 표시하는 독립 테스트 UI입니다.
기본 카메라는 S/N `24346077`, 라이트는 `COM3` / `9600 bps`입니다.
FastAPI가 제공하는 `/camera-test` HTML 화면이며 `uv sync --extra gui`로 설치합니다.

```powershell
cd D:\Code\inmold_sw
.\.venv\Scripts\python.exe Cam_test.py
```

실행하면 [Cam_test](http://127.0.0.1:7860/camera-test)가 열리고 최신 카메라 영상을 약 0.2초마다 갱신합니다.
카메라 연결에 실패하거나 수신 스레드가 종료되면 3초 간격으로 재연결합니다.
**카메라 연결 해제**를 직접 누르면 자동 재연결도 중지합니다.
`main.py` 검사 서버에서도 `/camera-test`를 열어 같은 진단 화면을 사용할 수 있습니다.
별도 `Cam_test.py` 서버를 실행하려면 기존 서버가 사용하는 카메라·COM 포트·웹 포트를 먼저 해제하세요.

- **카메라 연결 / 게인·FPS 설정**: 카메라 일련번호, 게인, 촬영 FPS를 변경하고 재연결합니다. 노출은 마지막으로 적용한 값을 유지합니다.
- **카메라 노출 시간 (µs)**: 현재 저장값은 `200000 µs`(200 ms)입니다. **노출 적용 및 저장**을 누르면 실제 센서 노출을 변경하고 공통 `config/camera.yaml`에 저장합니다. 연결 중에는 재연결 없이 적용하며, 연결 해제 상태에서는 다음 연결에 사용합니다. 미리보기와 ROI 결과는 별도 밝기 배율 없이 카메라 영상을 표시합니다.
- **현재 프레임에서 ROI 추출**: 원본 프레임의 직물 상·하단 경계를 검출하고 ROI 영상·품질 상태를 표시합니다. 추출 중에도 실시간 영상은 갱신됩니다.
- **Color · Mono 두 장 저장**: **이미지 이름**을 입력하고 버튼을 누르면 같은 최신 카메라 프레임에서 원본 해상도의 Color PNG(uint8 RGB)와 Mono PNG(uint8 흑백)를 함께 저장합니다. Mono는 RGB 프레임을 그레이스케일로 변환한 영상입니다. 카메라가 `Mono8`로 촬영 중이면 Color PNG도 세 채널 값이 같은 흑백 영상입니다. 예를 들어 `Case01_시편01`은 `data/cam_test/YYYY-MM-DD/Case01_시편01_Color.png`와 `Case01_시편01_Mono.png`로 저장합니다. 입력한 이름 끝의 `.png`는 한 번 제거한 뒤 Color·Mono 접미사를 붙입니다. 둘 중 하나라도 같은 이름이 있으면 두 파일 모두 같은 번호를 붙여(`Case01_시편01_1_Color.png`, `Case01_시편01_1_Mono.png`) 기존 파일을 보존합니다. 이름을 비우면 `cam_<촬영 시각>_<고유값>`을 공통 이름으로 사용합니다. 경로나 Windows에서 사용할 수 없는 파일 이름은 오류로 안내합니다. 화면의 **Color · Mono 이미지 다운로드**에서 두 파일을 각각 받을 수 있습니다. ROI 경계나 마스킹은 저장하지 않으며, 저장 중에도 실시간 프리뷰는 갱신됩니다. 한 파일이라도 저장에 실패하면 이번에 생성한 두 파일을 정리합니다. 연결이 끊겼거나 최근 2초 이내 프레임이 없으면 저장하지 않습니다. `--capture-dir <폴더>`로 저장 위치를 바꿀 수 있으며 기본 저장 폴더는 Git에서 제외합니다.
- **실시간 화면에 최근 ROI 경계 표시**: 마지막 추출 경계를 겹쳐 표시합니다. 초록색은 품질 통과, 주황색은 검토 필요입니다. ROI 결과 영상은 추출 시점의 정지 영상입니다.
- **RS232 연결**: 포트와 전송 속도를 선택해 연결합니다. 연결만으로 밝기 명령을 보내지 않습니다.
- **이 조명 적용 / 4개 조명 적용**: 본 UI와 같은 네 조명 그룹을 제어합니다. 왼쪽 아래 면조명 CH1+CH2, 왼쪽 위 바 조명 CH3, 오른쪽 위 바 조명 CH4, 오른쪽 위 면조명 CH5+CH6입니다. 면조명은 두 채널에 같은 밝기를 전송하고 두 ACK를 모두 확인해야 적용 완료로 표시합니다.
- **전체 끄기 (0%)**: CH1~CH6에 0% 명령을 전송합니다. 각 조명에 속한 채널이 모두 ACK를 받은 경우에만 해당 조명의 슬라이더를 0으로 갱신합니다. 부분 실패 시 성공한 채널과 이후 전송 중단을 표시합니다.

슬라이더 값은 전송할 값이며 장치에서 읽은 실제 밝기가 아닙니다. 전송 실패 시 결과에 오류가 표시됩니다.
종료는 실행한 터미널에서 `Ctrl+C`를 누릅니다. 종료 시 카메라·RS232 포트를 닫으며, 추가 밝기 명령은 보내지 않습니다.
카메라·포트·웹 주소는 `--camera-serial`, `--light-port`, `--baudrate`, `--host`, `--port`로 지정할 수 있습니다.
ROI 경계 설정은 `--roi-config config/roi_gabor_boundary.yaml`로 지정합니다.

### 공통 카메라 설정

본 검사 UI와 Cam_test는 시작할 때 [config/camera.yaml](config/camera.yaml)을 읽습니다.
현재 저장된 값은 다음과 같습니다. UI에서 값을 저장하면 파일 내용도 바뀝니다.

```yaml
exposure_us: 200000
pixel_format: Mono8
```

`exposure_us`는 센서가 빛을 받는 시간이며 단위는 µs(마이크로초)입니다.
`pixel_format`은 `Mono8` 또는 `BayerGR12`를 지정합니다. 카메라 제어 클래스의
파일 없는 기본값은 10 ms·`BayerGR12`이지만, 두 UI는 위 설정 파일을 읽어 시작합니다.
카메라 연결 시 자동 노출을 끄고 이 값을 설정합니다. 기기가 지원하는 범위로 제한될 수 있습니다.
Cam_test에서 **노출 적용 및 저장**을 누르면 실제 적용된 노출값을 파일에 저장합니다.
기기가 요청값을 지원 범위로 조정하면 조정된 값을 입력란과 config에 반영합니다.
**저장된 노출 불러오기**와 페이지 새로고침은 입력란만 갱신하며, 장치 적용은 적용 버튼으로 진행합니다.
노출 적용 실패 시 파일은 유지됩니다. 장치 적용 후 저장에 실패하면 두 결과를 구분해 표시합니다.
본 검사 UI는 다음 실행 때 저장된 노출을 사용합니다. 별도 파일은 두 프로그램의 `--camera-config` 옵션으로 지정할 수 있습니다.
파일이 없거나 노출이 0 이하·숫자 아님·무한대이면 오류를 표시하고 카메라를 시작하지 않습니다.

### 자동 ROI — 원본 프로젝트 코드 적용

Main UI의 **자동 ROI 설정**과 Cam_test의 **자동 ROI 추출**에서 **낮음·중간·높음** 검증 강도를 선택합니다.
기본값은 **낮음**입니다. 세부 ROI 기준 슬라이더를 조절하면 아래 기준 사이에서 경계 검증 값들도 비례 조절됩니다.

| 검증 강도 | 점수 기준 | 경계 일치 최소 | 가로 지지 최소 | 끊김 최대 | 구간별 지지점 최소 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 낮음 · 완화 | 0.25 | 35% | 40% | 60% | 0개 |
| 중간 | 0.40 | 55% | 70% | 25% | 2개 |
| 높음 · 엄격 | 0.55 | 70% | 85% | 15% | 3개 |

직선 오차·상하단 각도 차이·높이 변화·RANSAC 잔차 허용치도 함께 조절됩니다.
낮음에서는 일부 가로 구간에 지지점이 없어도 전체 경계의 지지 범위·일치 비율이 충분하면 사용할 수 있습니다.
실제 경계점이 부족하거나 경계가 없고 상·하단 순서가 잘못된 경우에는 자동으로 통과시키지 않습니다.
단계 선택과 슬라이더 이동은 미리보기이며, **ROI 기준 적용 및 저장**을 눌러야 공통 `config/roi_gabor_boundary.yaml`에 저장됩니다.
다음 ROI 추출·측정부터 적용됩니다. 별도 ROI config를 지정한 실행에서는 해당 파일에 저장합니다.
**ROI 기준 불러오기** 또는 페이지 새로고침으로 최신 저장값을 입력란에 반영합니다.
이 값은 종합 경계 품질의 최소 점수이며, 함침율 수치가 아닌 ROI 경계 검증에 사용합니다.
경계 지지점·직선 피팅·기하 검증은 선택한 단계의 기준으로 적용됩니다.
각 추출 결과에는 추출 당시 적용한 점수 기준과 점수 조건 통과 여부, 다른 검증의 보류 사유를 표시합니다.
예를 들어 점수 `0.34`, 기준 `0.30`이면 점수 조건은 통과해도 하단 경계 일치 비율 부족으로 보류될 수 있습니다.
기준을 저장한 뒤에는 ROI를 다시 추출하거나 다시 측정해야 합니다. 이전 결과는 자동으로 재평가하지 않습니다.

[참고 저장소의 ROI 코드](https://github.com/sepengsu/in-mold-surface-impregnation-inspection/tree/dcaafcd5a03903699161b2ded5d2aa1add1c8b8c/src/roi)를
`src/roi`에 가져왔습니다. 적용 버전은 커밋 `dcaafcd5a03903699161b2ded5d2aa1add1c8b8c`의
`gabor_boundary_quality_v5`입니다. Gabor 특징 → 열 구간별 경계 후보 → DP 경로 선택 →
RANSAC 직선·품질 검증 순서로 직물의 상·하단을 검출합니다. 출처와 연결 방식은
[src/roi/UPSTREAM.md](src/roi/UPSTREAM.md)에 기록했습니다.

- 카메라 원본 해상도·좌표를 유지합니다. 리사이즈나 원근 변환을 하지 않습니다.
- 기울어진 경계는 열별 마스크로 보존하고, 마스크의 외접 사각형을 타일 추론합니다.
- ROI 밖 픽셀은 입력에서 0으로 처리합니다. 검사 GUI의 P1~P3는 각 256×512px 전체가 ROI 안에 들어가야 하며, 경계를 벗어나면 추론·판정을 중단합니다.
- `PASS` 또는 `RECOVERED`인 경계만 자동 검사에 사용합니다. `NEEDS_REVIEW`나 검출 실패는 추론·판정을 중단하고 이유를 표시합니다.
- Cam_test는 버튼을 누른 프레임에서 추출합니다. 검사 GUI는 측정할 때마다 해당 입력에서 다시 추출합니다. 단일 프레임에는 다중 노출 합의 점수를 부여하지 않습니다.

`config/roi_gabor_boundary.yaml`은 참고 프로젝트 설정에서 현재 2046×2046 직물 원본에 맞춰
Gabor 필터와 검증 단계를 조정한 값입니다. ROI 검출은 실시간 갱신마다 실행하지 않습니다.
촬영 조건을 고정하고 실제 경계와 추출 결과를 확인하며 검증 강도를 조정하세요.

기존 고정 사각형을 사용하려면 `config/preprocess.yaml`의 `auto_roi.enabled`를 `false`로
바꾸고 `roi` 좌표·크기를 설정합니다. 검토 필요 결과에서 고정 ROI로 자동 전환하지 않습니다.
ROI 의존성을 포함해 설치하려면 다음 명령을 실행합니다.

```powershell
uv sync --extra model --extra gui
```

### RS232_test — 라이트 전용 테스트 UI

`RS232_test.py`는 카메라·모델 없이 RS232 6채널 조명(CH1~CH6)을 테스트합니다.

기본 주소는 [RS232 테스트](http://127.0.0.1:7861/rs232-test)입니다.
`main.py` 검사 서버에서도 `/rs232-test`를 열 수 있습니다.
실행 시 포트를 자동으로 열지 않습니다. 포트(기본 `COM3`)와 전송 속도(기본 `9600 bps`)를
선택한 뒤 **RS232 연결**을 누릅니다. 별도 프로세스의 Cam_test나 검사 GUI가 같은 COM 포트를
사용 중이면 그 프로세스에서 연결을 해제하거나 종료한 뒤 연결하세요. 같은 `main.py` 서버의
검사·진단 페이지는 조명 연결을 공유합니다.

- **6채널 적용**: CH1부터 CH6까지 차례로 전송하며 각각 ACK를 확인합니다.
- **전체 끄기 · 0%**: 여섯 채널에 0%를 전송하며 ACK를 받은 채널의 슬라이더만 0으로 바꿉니다.

슬라이더 변경만으로 전송하지 않으며 연결·연결 해제·종료도 밝기를 변경하지 않습니다.
ACK 실패 시 이후 채널 전송을 중단하고 성공한 채널까지 표시합니다. 재연결 후 다시 적용하세요.
최근 ACK는 명령 수신 기록이며 실제 광량이나 장치에서 읽어온 현재 밝기가 아닙니다.
이력과 ACK 기록은 메모리에만 저장되며, 연결을 해제하면 채널별 ACK 표시는 초기화됩니다.
실행한 터미널의 `Ctrl+C`로 종료합니다.

`--light-port`, `--baudrate`, `--host`, `--port`, `--no-browser` 옵션을 지원합니다.

## 프로젝트 개요

`vision_data` 기반 전처리·grayscale U-Net에 참고 저장소의 자동 ROI를 연결한 추론 구성입니다.
`src/postprocess`는 전처리 metadata를 이용해 타일 예측을 ROI와 원본 이미지 좌표로 복원합니다.

## 구성

- `src.roi`: 참고 저장소의 Gabor·DP·RANSAC 경계 검출 및 품질 검증.
- `src.preprocess`: uint8 이미지 로드 → 자동/고정 ROI → CLAHE → 겹치는 타일과 좌표 metadata. 리사이즈하지 않습니다.
- `src.model`: `vision_data`의 1채널/3채널 U-Net 체크포인트 로드 및 타일별 대상 픽셀 확률 예측.
- `src.postprocess`: 패딩을 제외하고 겹친 타일 확률 평균 → 이진 마스크 → 원본 좌표 복원.

전처리에는 NumPy, OpenCV, PyYAML, SciPy, scikit-image가 필요합니다. 모델 추론에는 PyTorch도 필요합니다.

```powershell
uv sync --extra model
```

## 사용 예시

기본 설정은 자동 ROI입니다. 먼저 Cam_test에서 경계와 품질 상태를 확인합니다.
고정 ROI를 사용할 때는 자동 검출을 끄고 좌표와 크기를 실제 이미지에 맞게 수정합니다.
체크포인트와 전처리 설정은 모델 학습 때 사용한 것과 일치해야 합니다.

```python
from src.preprocess import load_config, preprocess_image
from src.model import load_checkpoint, predict_tiles
from src.postprocess import (
    impregnation_pct, merge_probabilities, restore_original_mask, threshold_mask,
)

config = load_config("config/preprocess.yaml")
result = preprocess_image("path/to/image.png", config)

model, checkpoint = load_checkpoint("model/best_model.pt", device="cpu")
tile_probabilities = predict_tiles(model, result["patches"], batch_size=8)
roi_probability = merge_probabilities(tile_probabilities, result["metadata"])
roi_detected = threshold_mask(roi_probability, checkpoint["threshold"])
full_detected = restore_original_mask(roi_detected, result["metadata"])
print(impregnation_pct(roi_detected, result["valid_mask"]))  # 유효 직물 픽셀 기준 함침율 (%)
```

`roi_detected`와 `full_detected`는 bool 배열입니다. 마스크 PNG는
`(full_detected.astype("uint8") * 255)`로 저장할 수 있습니다.
원본 ROI 밖은 `False`로 채웁니다. ROI 밖을 함침율 계산에 포함하지 마세요.

이진 결과의 `True`는 선택한 체크포인트의 검출 대상 픽셀입니다. 현재 체크포인트 로더는
`architecture=grayscale_unet`(Exposure 1채널)과
`architecture=grayscale_unet32_3class`(Background/Exposure/Weldline 3채널)를
지원합니다. 3클래스 모델은 학습 코드의 `predict_binary`와 동일하게
`P(Exposure) + P(Weldline)`을 합쳐 이진 검출 영역과 함침율을 계산합니다.
사용한 대상 클래스는 UI 상태·측정 결과·이력 메타데이터에 표시됩니다.
참고 프로젝트의 benchmark 모델은 대상이 아닙니다.
현재 저장소의 `model/best_model.pt`는 3클래스 체크포인트입니다.
`main.py`의 기본 체크포인트는 `model/best_model.pt`입니다. 다른 모델을 쓰려면
`--checkpoint`로 경로를 지정하세요.

## 검사 GUI

`main.py`는 FastAPI 서버와 HTML·JavaScript 화면(`src/web/static`)을 실행합니다.
검사 엔진은 `src/inspection/engine.py`, 카메라·RS232 진단은 `src/diagnostics`, HTTP API는
`src/web`에 있습니다. 추론·카메라·조명·이력 저장 로직은 기존 모듈을 사용합니다. Basler 카메라에서
받은 최신 RGB 프레임을 메모리에서 grayscale로 변환한 다음 위 전처리·추론·복원
흐름에 전달합니다. 체크포인트가 검출한 대상 픽셀은 빨간색으로 표시합니다.

```powershell
uv sync --extra model --extra gui
uv run --extra model --extra gui python main.py
```

카메라 드라이버가 없다면 `scripts/setup_basler.ps1 -CheckOnly`로 확인하고,
필요할 때 `scripts/setup_basler.ps1`을 실행합니다. 설치 스크립트는 Windows의
Basler pylon Runtime과 프로젝트 `.venv` 의존성을 구성합니다. 조명 제어는
`LIGHT_SERIAL_PORT` 환경 변수(기본 `COM3`)로 포트를 지정합니다.

자동 ROI는 측정 프레임에서 품질 검증을 통과해야 합니다. 고정 모드에서는
`config/preprocess.yaml`의 ROI를 실제 카메라 영상 크기·위치에 맞춰야 합니다.
P1~P3은 각각 **가로 256 × 세로 512px**의 측정 영역이며, 가로 중심 간격은 **547px**입니다.
P2를 ROI 가로 중앙에 놓고 P1·P3를 좌우로 배치합니다. 세로 위치는 각 영역의 가로 중심에서
ROI 상·하단의 중간을 따릅니다. 기울어진 ROI에서는 각 영역의 y 좌표가 다를 수 있습니다.
2046px 폭의 ROI에서는 x 범위가 각각 `[348, 604)`, `[895, 1151)`, `[1442, 1698)`입니다.
크기는 원본 픽셀 기준이며, 회전·리사이즈·패딩이나 임의 위치 보정은 하지 않습니다.
ROI가 너무 작거나 한 영역이라도 ROI 밖으로 나가면 오류를 표시하고 추론·판정을 중단합니다.

ROI 검출과 CLAHE 설정은 유지하며, GUI 검사에서는 전체 ROI의 슬라이딩 타일을 생성하지 않습니다.
각 측정 영역을 위·아래 **256×256px 두 장**으로 나눠 **총 6장만 추론**합니다.
추론 순서는 P1 위·아래 → P2 위·아래 → P3 위·아래이며, 겹침 없이 세로로 복원합니다.
각 점수는 `100 × (1 − 검출 대상 픽셀 수 / 131072)`입니다. 전체 영상에는 세 측정 영역의
예측만 빨간색으로 표시하고, 나머지 영역은 추론하지 않습니다. 대표값은 P1~P3 평균입니다.
함침율 합격 기준 설정과 PASS/FAIL 판정은 제거했습니다. 모델의 픽셀 분할 임계값은
체크포인트 값(현재 0.5)을 사용하며, ROI 경계 품질 검증은 유지합니다.
측정 전에는 결과가 비어 있고, 최근 이력은 DB에서 복원합니다.
카메라·모델 연결 상태는 화면에 표시됩니다.

화면 왼쪽 **검사 모드**에서 `일반 모드`(기본값)와 `공인인증 평가 모드`를
선택할 수 있습니다. 선택한 모드는 측정 결과와 최근 이력에 표시하고,
저장된 이력의 `촬영·검사 조건` 및 CSV의 촬영 조건에 기록합니다.
공인인증 평가 모드는 `src/PCE`의 별도 경로를 사용합니다. 입력 영상에서 회색조
임계값 150으로 어두운 영역을 추출하고 3×3 close/open 후 연결요소를 찾습니다.
면적 500~20000px(현재 2046×2046 촬영본의 사각형은 약 10000~13000px),
가로·세로 비율 0.7~1.3, 영상 경계에서 10px 초과 떨어진
영역이 정확히 3개일 때 왼쪽부터 P1~P3로 지정합니다. 각 연결요소의 최소 회전
사각형을 구해 기울기를 보정하고, 보정된 크롭 전체를 256×256px로 확대해 한 장씩
추론합니다. 예측은 보정된 크롭의 원래 픽셀 크기로 되돌려 점수를 계산합니다.
원본 RGB가 순수 검정 `(0, 0, 0)`인 픽셀은 분자와 분모에서 제외해 선택한
모델의 검출 대상 픽셀 비율과 함침율을 계산합니다. P1~P3의 유효 픽셀 수는
결과와 이력 메타데이터에 기록합니다. 전체 결과 영상에는 원본을 유지하고
P1~P3 측정 영역 박스와 예측 색상을 겹쳐 표시합니다. P1~P3 개별 결과도
보여 줍니다. 검출 경계 자체가
불규칙하거나 밝은 픽셀이 회전 사각형 안에 있으면
회전 보정 후에도 가장자리가 일부 남을 수 있습니다. 공인인증 평가용 합격·불합격
판정 기준은 아직 설정되지 않았습니다. UI의 **자동 ROI 설정**은 일반 모드의
Gabor 경계 검증용이며, 공인인증 평가 모드의 어두운 영역 임계값 150은 바꾸지 않습니다.

### 입력 선택과 실행 설정

템플릿의 3열 화면(입력·조명·ROI 설정 / 검사 영상·P1~P3 / 결과·이력)을
실제 검사 데이터로 연결했습니다. **검사 입력**에서 `이미지 파일`을 선택하면
업로드한 RGB 이미지에도 동일한 전처리·U-Net·후처리를 적용합니다. 파일의
자동 ROI도 파일 입력에서 다시 검출합니다. 고정 모드에서는 파일 크기가 설정한 ROI를
포함해야 하며 자동 리사이즈하지 않습니다. 템플릿의 `assets/*.png`는 화면 시안이므로 검사 결과로 사용하지 않습니다.

장비 없이 파일 검사 화면을 실행할 수 있습니다.

```powershell
uv run --extra model --extra gui python main.py --no-camera
```

모델·전처리·추론 장치와 카메라는 실행 인자로 지정할 수 있습니다. 기본값은
프로젝트 루트의 전처리 설정과 체크포인트, CPU, 배치 크기 8입니다.

```powershell
uv run --extra model --extra gui python main.py --config config/preprocess.yaml --checkpoint model/best_model.pt --device cpu --batch-size 8 --camera-serial 12345678
uv run --extra model --extra gui python main.py --no-camera --checkpoint model/best_model.pt --no-browser --host 127.0.0.1 --port 7860
uv run --extra model --extra gui python main.py --no-camera --checkpoint model/best_model.pt
```

`--device cuda:0`은 CUDA를 사용할 수 있는 환경에서 지정합니다. 카메라 연결에
실패하면 화면의 **카메라 연결 / 재시도**를 누릅니다. 연결이 끊겼거나 최근 2초
이내 새 프레임이 없으면 측정을 거부하고, 오류를 결과 영역에 표시합니다.
모델 로드 실패도 시스템 상태에서 확인할 수 있습니다.

카메라 프리뷰 아래 **카메라 촬영 형식**에서 `GrayScale · Mono8` 또는
`RGB Color · BayerGR12`를 선택하고 **촬영 형식 적용 및 저장**을 누르면
카메라를 재연결해 적용합니다. 값은 `config/camera.yaml`의 `pixel_format`에 저장됩니다.
현재 Basler `acA2040-25gc`는 카메라 자체의 RGB8 출력을 지원하지 않아
컬러 촬영은 BayerGR12로 받은 뒤 RGB8로 변환합니다. Mono8은 표시와 검사
호환을 위해 세 채널이 같은 RGB 배열로 전달됩니다. 카메라가 연결되지 않은
파일 검사 모드에서는 선택값을 저장하고 다음 카메라 연결부터 적용합니다.

본 UI의 **4개 조명 설정**을 열면 실제 조명 위치별로 밝기를 조절할 수 있습니다.
[Light.md](Light.md)의 배정은 다음과 같이 적용됩니다.

| 본 UI 조명 | RS232 채널 | 동작 |
| --- | --- | --- |
| 왼쪽 아래 면조명 | CH1 + CH2 | 두 채널에 같은 밝기 적용 |
| 왼쪽 위 바 조명 | CH3 | 단일 채널 적용 |
| 오른쪽 위 바 조명 | CH4 | 단일 채널 적용 |
| 오른쪽 위 면조명 | CH5 + CH6 | 두 채널에 같은 밝기 적용 |

**이 조명 적용**을 누르면 선택한 조명에만 전송합니다. 슬라이더 변경만으로는 전송하지 않습니다.
**설정 적용 후 닫기**는 네 조명의 설정을 CH1~CH6에 차례로 전송하고 각각 ACK를 확인합니다.
면조명은 두 채널 모두 ACK를 받아야 적용 완료로 표시하며, 한 채널만 성공하면 부분 적용으로 표시합니다.
실패하면 설정창과 오류 메시지를 유지하고 성공한 채널 및 이후 전송 중단을 표시합니다.
**닫기**는 추가 전송 없이 창을 닫습니다. 표시되는 평균은 네 조명의 선택값 평균이며,
슬라이더 초기값과 ACK 기록 모두 장치에서 읽어온 현재 광량이 아닙니다.

프로그램 시작 시 RS232 포트(기본 COM3, 9600bps, 8N1)를 열어 유지하고,
종료 시 닫습니다. 연결만으로 밝기 명령을 보내지 않으며, 이때 시스템 상태는
`RS232 OPEN · 제어 대기`입니다. 이는 PC의 포트가 열린 상태를 뜻합니다.
라이트 컨트롤러의 응답 확인은 실제 제어 명령에 대한 ACK를 받은 뒤 표시합니다.

### 공통 조명값 저장·불러오기

본 검사 UI와 카메라 테스트 UI는 [config/lighting.yaml](config/lighting.yaml)을 함께 사용합니다.
각 조명 슬라이더 위에 **설정 밝기 N%**가 표시되며, 슬라이더 이동·설정 불러오기·전체 끄기 후 갱신됩니다.
이 비율은 전송할 선택값이며, 장치에서 읽은 실제 광량과는 다릅니다. 마지막 전송의 ACK 결과는 별도로 표시합니다.
각 화면에서 네 조명의 밝기를 정한 뒤 **조명값 저장**을 누르면 파일에 저장합니다.
**저장값 불러오기**는 파일의 최신 값을 슬라이더에 반영합니다. 프로그램 시작과 페이지 새로고침 때도 자동으로 불러옵니다.
한 UI에서 저장한 값은 다른 UI의 다음 실행·새로고침·불러오기 때 반영됩니다.

저장·불러오기·슬라이더 변경은 장치에 밝기 명령을 보내지 않습니다.
실제 출력은 **이 조명 적용**, 전체 적용 또는 전체 끄기 버튼을 눌러 변경합니다.
적용과 저장은 각각 별도 동작이며, 적용만으로 저장된 파일이 바뀌지는 않습니다.
최초 설정 파일은 네 조명 모두 `0%`로 제공하며 장치에서 읽은 실제 밝기가 아닙니다.

| 설정 키 | 조명 / 채널 |
| --- | --- |
| `left_lower_panel` | 왼쪽 아래 면조명 / CH1 + CH2 |
| `left_upper_bar` | 왼쪽 위 바 조명 / CH3 |
| `right_upper_bar` | 오른쪽 위 바 조명 / CH4 |
| `right_upper_panel` | 오른쪽 위 면조명 / CH5 + CH6 |

파일에는 `version: 1`과 `brightness_percent` 아래 위 네 키의 `0~100` 숫자를 지정합니다.
잘못된 설정을 불러오면 오류를 표시하고 현재 슬라이더 값을 유지합니다.
시작 시 파일이 없거나 잘못되었으면 오류와 함께 화면 기본값 `0%`를 표시하며 장치에는 전송하지 않습니다.
저장 시에는 네 값을 모두 검증하고 임시 파일을 완성한 뒤 교체하므로, 저장 실패 시 기존 설정 파일이 보존됩니다.

결과는 P1~P3 평균·개별 함침율, 측정 시각, 소요 시간과 자동 저장 상태를 표시합니다.
INSPECTION RESULT와 각 History 항목에 **측정 소요 시간**을 초 단위, 소수점 셋째 자리까지 표시합니다.
서버에서 측정 요청 처리를 시작한 시점부터 프레임 취득, ROI 검출, 전처리, 추론,
함침율 계산과 결과 이미지 생성이 완료될 때까지를 단조 시계로 측정합니다.
서버 대기열·네트워크 전송·브라우저 렌더링·이력 파일 저장 시간은 포함하지 않습니다.
작은 화면에서는 세로 배치로 전환해 스크롤할 수 있습니다.

### 이력 자동 저장 · 통계 보기 · CSV

측정이 완료되면 `data/history/history.sqlite3`에 결과를 저장합니다. 별도 DB 서버나
추가 패키지는 필요하지 않습니다. 원본과 결과 영상은
`data/history/images/YYYY-MM-DD/<측정 ID>/original.png`, `result.png`에 원본 픽셀의
PNG로 보존합니다. 각 기록은 P1~P3 함침율, 평균, 측정 시각·소요 시간·입력 종류,
ROI와 세 측정 영역 좌표, ROI 검출 정보, 모델 체크포인트 경로·SHA256·임계값을 포함합니다.
카메라 입력은 노출 설정·카메라 일련번호·측정 당시 UI 조명 설정값도 보존합니다.
조명 UI 값은 선택된 설정값이며 실제 광량이나 ACK로 확인된 적용값을 뜻하지 않습니다.
파일 입력에는 해당 촬영 조건을 추정해 채우지 않습니다.

History에는 DB의 최근 5건을 표시하고, 페이지 새로고침·프로그램 재시작 후에도 복원합니다.
DB에는 전체 기록을 보존하며 자동 삭제하지 않습니다. 두 PNG가 완전히 저장된 뒤 DB에 기록하고,
저장 실패 시 결과를 화면에 유지하면서 `이력 저장 실패`와 `미저장`을 표시합니다.
저장 데이터와 CSV는 `.gitignore`로 Git에서 제외합니다.

History 제목 옆 **통계 보기**를 누르면 별도 화면으로 이동합니다.
시작일·종료일·입력 종류로 조회하고, 선택 기간의 측정 수·평균 함침율·평균 소요 시간과
P1/P2/P3 평균·측정 평균 최솟값/최댓값을 확인합니다. 날짜는 한국 시간 기준이며 종료일 전체를 포함합니다.
목록은 50건씩 이전/다음 페이지로 이동합니다. 통계 집계는 현재 페이지가 아닌 전체 검색 결과 기준입니다.
행을 선택하면 저장 원본·결과, 동일 좌표로 복원한 P1~P3 이미지, 촬영·검사 조건을 볼 수 있습니다.
**검사 화면으로** 버튼은 검사 화면으로 돌아가 최신 History를 불러옵니다.

**CSV 내보내기**는 현재 날짜·입력 조건에 맞는 전체 기록을
`data/history/exports/inspection_<시각>_<고유값>.csv`로 생성합니다. 화면에 표시되는
CSV 다운로드 파일을 눌러 받습니다. Excel에서 한글을 읽을 수 있도록 UTF-8 BOM으로 저장하며,
소수점 표시 전의 측정값·시간과 이미지 상대 경로·좌표·촬영 조건을 포함합니다.
기록 수와 관계없이 행 단위로 내보내며, 조회 조건을 변경하면 이전 다운로드 링크를 초기화합니다.

통계 화면의 **전체 측정 이력 초기화**를 열어 삭제 확인을 선택한 뒤 버튼을 누르면
조회 필터와 관계없이 전체 측정 기록, 저장된 원본·결과 PNG, 앱이 생성한 CSV
내보내기 파일을 삭제합니다. 초기화 후 통계와 검사 화면의 최근 이력을 즉시 갱신합니다.
`data/PCE` 등 검사 입력 데이터와 모델 파일은 삭제하지 않습니다.

### PCE 검증용 20건 오차표

`data/검증용 20`의 Case 폴더마다 있는 이미지 1장에 공인인증 평가 모드와 같은
P1~P3 회전 보정·추론·검정 픽셀 제외 규칙을 적용합니다. `정답지.txt`의 폴더별
값은 **P2 함침율 정답**이므로 P2 예측값만 비교합니다. P1/P3 예측값은
오차 계산에 포함하지 않습니다.

```powershell
.\.venv\Scripts\python.exe tests\inference\report_pce20.py
```

기본 모델은 `model/best_model.pt`이며 `--checkpoint`, `--data-root`,
`--output-dir`, `--device`를 바꿀 수 있습니다. 결과는
[`tests/inference/results/pce20_error_table.png`](tests/inference/results/pce20_error_table.png)와
같은 이름의 CSV·JSON으로
저장됩니다. 표의 차이는 `P2 예측 - P2 정답`(%p), 오차율은
`|차이| / P2 정답 × 100`(%)입니다. 전체 20건과 검증용 12건의 MAE·평균 오차율을
별도로 표시합니다.

현재 `best_model.pt`(SHA256 `4a070ce0…`)로 실행한 P2 기준 결과는 다음과
같습니다. 모델이나 입력 데이터가 바뀌면 스크립트를 다시 실행해 갱신하세요.

| 범위 | 건수 | MAE (%p) | 평균 상대 오차율 |
| --- | ---: | ---: | ---: |
